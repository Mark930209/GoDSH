# 文本工具调用协议：方言、解析要点与自动降级的坑

> n1n-prompt-tools 插件已删除（2026-11-06），但其验证过的模型行为、协议方言与两次真实
> 故障的教训值得保留。做同类"文本协议适配器"（自己或他人的插件）时直接照这份避坑。
> 相关背景：[prompt-cache-investigation.md](prompt-cache-investigation.md)、
> [dsh-conversation-internals.md](dsh-conversation-internals.md)。

## 1. 真实出现过的调用方言（n1n 网关实测）

同一模型会在下列写法之间漂移，解析器必须全部接受：

| 方言 | 形态 | 备注 |
| --- | --- | --- |
| 自定义标记 | `@@TOOL@@ {"name":"...","arguments":{...}}` | 提示词协议约定的形式 |
| XML 工具块 | `<tool_call>name<arg_value>...` / `<tool_call>{"name":...}</tool_call>` | 两种子形态都出现过 |
| function 标签 | `<function=read>...` | |
| DSML | `<｜DSML｜ invoke name="...">` | **竖线是 U+FF5C 全角**；泄漏进正文时会双写成 `<｜｜DSML｜｜`（每个竖线翻倍），解析和检测都要按双竖线形态再匹配一遍 |

解析实现要点：

- **JSON 参数按花括号配平截取**（字符串态、转义态要跳过），不能找第一个 `}`。
- 参数闭合被截断（模型输出断了）时要能容错复原。
- 参数类型别靠猜：把工具 JSON Schema 的顶层参数类型随目录带进解析器（`argumentTypes`），
  数字参数才不会掉引号后被当成字符串。
- **分片健壮性要 fuzz**：流式 delta 会把协议文本切成任意碎片。曾用 1876 种分片回归
  （1 字符一片、7 字符一片、逐位置二分、三刀网格）对同一段真实泄漏文本重放，全部解析
  正确——**先 fuzz 证明解析器无罪，再去怀疑别的层**。这套方法论后来抓到的真凶是
  "出站剥工具和入站解析脱钩"（见 dsh-conversation-internals §4）。

## 2. "提到协议"与"尝试调用"必须区分（真实事故）

判断"模型想调工具但没调成"（触发降级/重试的入口）时，朴素做法是看可见文本里有没有
`@@TOOL@@`、`DSML`、`tool_call` 这些字面量。**这是错的**：模型（或人类让模型）正常
讨论这套协议时正文就含这些词，且该步天然没有解析出的调用——于是每次讨论都触发误判。

正确判据 = **调用形态要求 body** + **剔除代码块/行内代码**：

```
@@TOOL@@\s*\{            ← 标记后必须紧跟 JSON 开头
<tool_call\s*>\s*\S      ← 开标签后必须非空
<function\s*=\s*[^>\s]+  ← 带名字
[|｜]{1,2}\s*DSML\s*[|｜]{1,2}\s*invoke\s+name\s*=   ← 单双竖线都收
```

先 `text.replace(/```[\s\S]*?```|`[^`\n]*`/g, ' ')` 再匹配。注意每个 marker 要和它自己的
`\s*\{` **拼成一个分支**，不能 marker 列表和 body 模式分开 `join('|')`——那样裸 marker
仍然会单独命中。（两个 bug 都实际发生过。）

这个误判的真实代价：调查插件问题时，助手在回复里大量引用协议字面量做解释，触发了连续
误判、把该路由永久降级——**讨论插件的对话把插件自己降级了**，同时制造了缓存前缀变化。

## 3. 自动降级（模型不遵协议时退回原生 tools）的设计要求

如果做同类 auto-detect，四条必须满足：

1. **连续证据计数**，一次失败不降级。默认 2 次连续，任何一次解析成功清零计数。
2. **并发突发只算一次**。同一毫秒内十几条流（子 agent 并发）同时失败是**一个**证据；
   实现上用 ≤2s burst 窗口合并。否则"连续 2 次"会被并发流量一秒内凑满。
3. **计数器按会话隔离**。`llm/stream` 钩子只有 `(options, next)`（见
   dsh-conversation-internals §4），唯一可用维度是 `options.sessionId`；子 agent 无
   sessionId，可有意共享一个匿名桶。只按 `provider::model` 计数会让子 agent 的失败
   把用户主会话连带降级。
4. **降级=前缀改写**。目录从系统提示词撤出、原生 `tools` 回来，切换后的第一个请求必吃
   一次完全未命中（实测 0%、0%、1%）。但**降级后的稳态命中率与不降级相同**（94% vs
   94%）——代价只在切换那一瞬，所以降级要慎重，但也不必恐惧；反复来回切换才是灾难。

另外：降级状态若是进程级持久化（Map，重启才复位），一次误判会毒化整个进程生命周期。
要么给恢复路径，要么把判定做到足够保守（上面 1–3 就是为此）。

## 4. 已实测的模型/网关行为

- `deepseek-v4.1-flash`（n1n/llm-api.net）：会按文本协议调用工具（10/10 成功），也会
  偶发把 DSML 写进正文（1393 字符那次）；解析器对它的分片健壮性经 fuzz 验证。
- `glm-5.3`：不遵循文本协议（沿用即失败），走原生工具。n1n 下不同模型对协议的遵守度
  差异很大，任何"文本协议"方案上线前要在目标模型上逐个实测。
- 网关**即使请求里没有 `tools` 字段，也可能返回原生 `delta.tool_calls`**（OpenAI 兼容
  形态）——入站解析必须同时处理文本方言和原生 tool_calls 两条路。
- 畸形 `tools` 数组（漏了 `type:"function"` 包装）网关回 503 而不是 400。
